# 功能规格模板

[English](spec.md) | 中文

## 概述

将本模板用于 `.scratch/<feature>/spec.md`。每个字段填写具体答案，或明确标注为未解决问题。此文件是模板，不是已批准的功能规格。

## 目录

- [基本信息](#identification)
- [问题与范围](#problem-and-scope)
- [设计与依赖](#design-and-dependencies)
- [验收与证据](#acceptance-and-evidence)
- [开发备注](#dev-note)

<a id="identification"></a>

## 基本信息

记录规格负责人及已经达成的约定。

| 字段 | 待填写内容 |
|---|---|
| 功能 | 名称与目录短名。 |
| 负责人 | 负责范围决策的人。 |
| 状态 | 草案、已确认、实施中或已验收。 |
| 范围确认 | 确认日期与范围依据，未确认前明确标为待定。 |
| 参考 | 相关产品、架构与决策文档。 |

<a id="problem-and-scope"></a>

## 问题与范围

- 用户与需求：描述使用者、场景与问题。
- 预期结果：描述可观察的用户结果。
- 纳入行为：列出最小完整流程。
- 排除项：列出明确不在本规格中的相邻工作。
- 约束：说明数据敏感性、权限、兼容性与部署前提。

<a id="design-and-dependencies"></a>

## 设计与依赖

- 现有负责方：指出要复用的包、服务、UI 与文档。
- 拟议变更：按需要说明职责、数据流、持久化与错误处理。
- 决策：长期理由链接到其 Agent Note，单独列出待定选择。
- 工单：列出 `issues/` 下的相对路径，分别注明前置依赖与负责的验收项。
- 迁移与恢复：指出受影响的持久数据、升级说明与恢复验证，或解释不适用的原因。

<a id="acceptance-and-evidence"></a>

## 验收与证据

每个可观察结果对应一项验收条件与一张负责工单。按[测试策略](../../testing.zh.md)选择与变更匹配的检查。

| 验收项 | 负责工单 | 验证方式 | 实际结果 |
|---|---|---|---|
| 描述用户可观察的结果。 | 填写工单相对路径。 | 指出检查、环境与所需输入。 | 记录实际证据，或标注未执行。 |

按适用性考虑单元、真实组合、e2e、录制会话快照、UI、文档与构建检查。说明不适用项与缺失的测试支持，不把计划执行的命令写成通过结果。

<a id="dev-note"></a>

## 开发备注

记录未解决问题、能够解决问题的人，以及每个问题阻塞的工作。创建单语本地文件时，将模板相对链接改为相对实际规格的位置，并移除模板语言切换链接。
