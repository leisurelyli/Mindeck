# 实施工单模板

[English](issue.md) | 中文

## 概述

每个可独立评审的工作单元使用一个 `.scratch/<feature>/issues/<NN>-<slug>.md` 文件。链接到功能规格及前置工单。此模板不分配实际实施任务。

## 目录

- [跟踪信息](#tracking)
- [工作定义](#work-definition)
- [验证记录](#verification-record)
- [完成条件](#completion)
- [开发备注](#dev-note)

<a id="tracking"></a>

## 跟踪信息

分诊与执行进度回答不同问题，两者分别记录。

| 字段 | 待填写内容 |
|---|---|
| 工单 | 编号与简短标题。 |
| 规格 | 所属规格的相对路径。 |
| 分诊 | 从 `needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix` 中选择一个，初始使用 `needs-triage`。 |
| 进度 | 未开始、进行中、阻塞或完成。 |
| 负责人 | 指定实施者，或明确标为未分配。 |
| 依赖 | 前置工单的相对路径，或明确填写无。 |
| 阻塞 | 后续依赖工单的相对路径，或明确填写无。 |

<a id="work-definition"></a>

## 工作定义

- 结果：描述此工单交付的行为或材料。
- 范围：指出负责的包、文件与文档。
- 排除项：指出已分配给其他工单的工作。
- 约束：链接适用规则与已有决策。
- 验收：列出可观察条件，按需要包含拒绝、恢复或清理行为。
- 测试计划：指出针对性检查与所需输入，解释不适用的测试类别。

<a id="verification-record"></a>

## 验证记录

记录实际执行情况，不包含密钥或私有业务数据。计划中的检查在实际执行前保留在测试计划中。

| 检查 | 环境与输入 | 结果 | 证据 |
|---|---|---|---|
| 实际命令或人工步骤。 | 相关版本与非敏感前提。 | 通过、失败，或未执行及其原因。 | 输出摘要或可访问的非敏感引用。 |

<a id="completion"></a>

## 完成条件

完成需要已确认验收条件的证据，不能只依据实现差异。

- [ ] 前置工单已满足，工作范围与规格一致。
- [ ] 验收条件已有验证记录，剩余限制已明确。
- [ ] 受影响的包文档与正式参考已更新。
- [ ] 必需的持久化变更确认、升级说明与快照已处理，或明确不适用。
- [ ] 已记录评审意见处理情况及后续工单交接。

<a id="dev-note"></a>

## 开发备注

记录阻塞原因与下一位负责人。说明 `wontfix` 的处置理由，该值不代表实施完成。创建单语本地工单时，调整模板相对链接并移除语言切换链接。
